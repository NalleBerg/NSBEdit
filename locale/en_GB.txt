REGEX_GUIDE_TITLE = Regex Guide
REGEX_GUIDE_LABEL = Containing
REGEX_GUIDE_NOTE = Ctrl+F focuses the search box. Search updates as you type.
REGEX_GUIDE_TEXT = T|Regex Reference Guide\nS|A small learning guide for NSBEdit's ECMAScript regex search\nB|Search the guide with plain text. Type in the box above or press Ctrl+F to jump to a topic.\nB|Examples stay short enough to remember and detailed enough to use.\n\nH|1. What a regex does\nB|A regular expression is a compact description of text you want to find.\nB|Instead of matching one exact string, a regex can match many related strings.\nB|NSBEdit uses std::wregex with ECMAScript syntax, so the examples below follow that style.\nC|error\nB|That matches the word error anywhere it appears.\n\nH|2. Literals and escaping\nB|Most letters and numbers mean themselves.\nB|Some punctuation is special, so it must be escaped with a backslash.\nC|\\.    a literal dot\nC|\\?    a literal question mark\nC|\\(    a literal opening parenthesis\nC|\\\\   a literal backslash\nB|If you want to match the exact text C:\\Temp, remember to escape each backslash in the regex.\n\nH|3. Character classes\nB|Character classes describe one character out of a set.\nC|[abc]     one of a, b, or c\nC|[^abc]    anything except a, b, or c\nC|[a-z]     a range\nC|[0-9A-F]  hex digits\nC|[._-]     a few punctuation characters\nB|Inside a class, the dash usually means a range, so put it first or last if you want a literal dash.\nC|[-_.]     literal dash, underscore, or dot\n\nH|4. Shorthand classes\nB|Shorthand classes are the fastest way to describe common text shapes.\nC|\\d    digit\nC|\\D    anything that is not a digit\nC|\\w    letter, digit, or underscore\nC|\\W    anything that is not a word character\nC|\\s    whitespace\nC|\\S    anything that is not whitespace\nC|.      any character except a line break\nB|A dot is broad; a shorthand class is usually more specific and safer.\n\nH|5. Anchors and boundaries\nB|Anchors do not match characters. They match positions.\nC|^      start of the searched text\nC|$      end of the searched text\nC|\\b    word boundary\nC|\\B    not a word boundary\nB|Use anchors when you want a full line, a word at the start, or a word at the end.\nC|^TODO\nB|That finds lines or strings that start with TODO.\nC|\\bfix\\b\nB|That finds the word fix, but not words like prefix or fixture.\n\nH|6. Repetition\nB|Quantifiers say how many times the previous token may repeat.\nC|*      zero or more\nC|+      one or more\nC|?      optional / zero or one\nC|{n}     exactly n times\nC|{n,}    n or more times\nC|{n,m}   between n and m times\nB|Quantifiers are greedy by default, so they try to consume as much as they can before backtracking.\nC|\\d+\nB|That finds one or more digits.\nC|\\s+\nB|That finds one or more whitespace characters.\nC|[A-Za-z_][A-Za-z0-9_]*\nB|That is a common identifier pattern: one starter character, then zero or more continuation characters.\n\nH|7. Grouping and alternation\nB|Parentheses group parts of the pattern so you can repeat them or remember them.\nC|(abc)       capture a group\nC|(?:abc)     group without capture\nC|a|b|c       match left or right\nB|Capturing groups become numbered left to right.\nC|(first)-(second)\nB|The first group becomes $1, the second becomes $2 in replacements.\nC|(cat|dog|fox)\nB|Alternation is useful when one field can hold a few known words.\nC|(?:https?|ftp)://\nB|A non-capturing group keeps the structure but skips a capture slot.\n\nH|8. Practical patterns\nB|These examples are small enough to adapt and large enough to be useful.\nC|TODO|FIXME\nB|Find either tag in notes, comments, or source files.\nC|\\b\\w+@\\w+\\.\\w+\\b\nB|A simple email-shaped pattern. It is not a full RFC validator, but it is useful for rough searches.\nC|\"[^\"]*\"\nB|Find quoted text on a single line.\nC|\\b\\d{4}-\\d{2}-\\d{2}\\b\nB|Find an ISO-style date such as 2026-06-15.\nC|\\b[A-Z][A-Za-z0-9_]*\\b\nB|Find simple identifier-like names that start with a capital letter.\nC|^\\s*$\nB|Find blank lines or lines that contain only spaces.\nC|\\b0x[0-9A-Fa-f]+\\b\nB|Find hex-style numbers such as 0x1A2B.\nC|\\b[+-]?\\d+(?:\\.\\d+)?\\b\nB|Find a simple integer or decimal number.\n\nH|9. Replacement ideas\nB|When you replace, capture groups let you reuse the parts you matched.\nC|Find:    ([A-Za-z]+) ([A-Za-z]+)\nC|Replace: $2, $1\nB|That swaps two words, so John Smith becomes Smith, John.\nC|Find:    (\\d{4})-(\\d{2})-(\\d{2})\nC|Replace: $3/$2/$1\nB|That turns 2026-06-15 into 15/06/2026.\nC|Find:    ^(.*)$\nC|Replace: [$1]\nB|That wraps each full line in square brackets.\n\nH|10. Common mistakes\nB|Most mistakes are small: a missing escape, a greedy quantifier, or an anchor in the wrong place.\nC|.txt\nB|This is not a literal dot and t x t; the dot means any character. Use \\.txt if you want a literal extension.\nC|(abc\nB|Unclosed groups are a syntax error.\nC|foo\\bar\nB|A single backslash usually starts an escape, so double it when you need a literal one.\nC|^word$\nB|That matches only a full line containing exactly word.\n\nH|11. How to think while searching\nB|Ask yourself three questions: what must be present, what may vary, and where should the match stop?\nB|If the answer is \"any character\", use a class or a dot. If the answer is \"the start or end\", use anchors.\nB|If the answer is \"repeat this part\", put it in a group before adding a quantifier.\nB|If you are unsure, search with a smaller pattern first and grow it one piece at a time.\n\nH|12. Notes for NSBEdit\nB|The editor's regex search uses the standard library engine, so prefer portable ECMAScript syntax.\nB|Containing search in this guide is literal, not regex-based, so you can jump by plain words or fragments.\nB|If you want a topic quickly, press Ctrl+F and type a word from the section you want.\nB|The search line is intentionally plain: no dialog, no regex mode, just the fastest possible topic finder.\n\nH|13. Try these searches\nC|digit\nC|capture\nC|boundary\nC|replace\nC|greedy\nC|anchor\nC|literal\nC|escape\nC|pattern
