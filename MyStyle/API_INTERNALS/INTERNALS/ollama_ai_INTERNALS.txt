================================================================================
  NSBEdit - AI Shell Internals (ollama_ai.cpp / ollama_ai.h)
================================================================================

  This note covers the standalone AI shell window that was extracted from
  NSBEdit.cpp into ollama_ai.cpp / ollama_ai.h.

FILES:
  ollama_ai.h                 Public entry point: Ne_ShowAiWindow(HWND parent)
  ollama_ai.cpp               Window class, menu logic, layout, owner-draw UI
  ne_ai_bootstrap.h/.cpp      Loads persisted AI bootstrap settings
  ne_ai_client.h/.cpp         Probes Ollama localhost availability

================================================================================
1. PURPOSE
================================================================================

  The AI shell is a separate top-level window owned by the main editor.
  It provides a lightweight local/cloud control surface for the current AI
  feature set without keeping the implementation inside NSBEdit.cpp.

  Current responsibilities:
    - Open and reuse the AI window.
    - Show current model, fallback model, cloud/local state, and sign-in state.
    - Offer menu actions for suggestion/agent model switching.
    - Offer local/cloud mode toggles and sign-in/sign-out actions.
    - Offer a Cloud maintenance action to check local models in-place and show
      its progress inside a modal dialog.
    - Append user prompts and Ollama responses to the output pane.
    - Keep the prompt box multiline so Shift+Enter can insert a newline.
    - Clear the prompt immediately when Send is pressed.
    - Persist the AI preferences through the existing profile store.
    - Provide a visible Copy code header for fenced blocks and a right-click
      Copy answer command for the whole rendered response.
    - Keep the rendered answer streaming live as plain text while reply
      chunks arrive, with code-copy affordances layered on top of fenced
      blocks.
    - Apply the lightweight live formatter to incoming chunks so code blocks
      and simple colour hints appear incrementally instead of waiting for the
      final render pass.

  Text wrapping:
    - Both RichEdit panes are created without horizontal scrolling.
    - EM_SETTARGETDEVICE(NULL, 0) is applied so each pane wraps to its current
      control width.
    - WM_SIZE reapplies the wrap target after the controls are resized.

  Reply rendering:
    - The reply parser normalises model escape text like u003c/u003e before
      it reaches RichEdit so sample HTML-like spans do not print literally.
    - Reply text is repainted live as plain text while the Ollama stream is
      still arriving.
    - Incoming chunks also feed the incremental live formatter so styled code
      blocks can appear before completion.
    - Fenced code blocks get a visible Copy code label and tracked copy
      range; richer colour, emoji, and markdown styling is a later pass.

================================================================================
2. ENTRY POINT
================================================================================

  void Ne_ShowAiWindow(HWND parent)

  Behaviour:
    - Reuses the existing AI window if it is already open.
    - Registers the NSBEditAIWindow class on first use.
    - Centers the window over the parent when possible.
    - Creates a WS_OVERLAPPEDWINDOW top-level window with modal-frame styling.
    - Calls ShowWindow / UpdateWindow / SetForegroundWindow after creation.

================================================================================
3. WINDOW STATE
================================================================================

  AiWindowState stores the runtime state for the window:
    - hHeader, hLog, hInput, hStatus
    - hSendBtn, hCopyBtn, hClearBtn, hCloseBtn
    - hFont, hPaneFont
    - dd (owner-draw button spec block)
    - model, fallback
    - cloudMode, signedIn

  The state object is allocated before CreateWindowExW and attached through
  WM_CREATE via GWLP_USERDATA. It is released on WM_DESTROY.

================================================================================
4. BOOTSTRAP AND PREFS
================================================================================

  Bootstrap defaults come from NeAiBootstrap_Get():
      - model defaults to qwen3-coder
    - fallback defaults to qwen2.5-coder:3b

    If older saved prefs still contain qwen2.5-coder:7b-instruct,
    qwen2.5-coder:7b, or qwen2.5-coder, Ai_LoadPrefs() normalises them back to
    qwen3-coder on startup so installed builds self-heal.

  Saved preferences are loaded in Ai_LoadPrefs() and written back by
  Ai_SavePrefs() using NeProfiles_SetStrSetting / NeProfiles_SetIntSetting.

  Persisted keys:
    - ai.model
    - ai.fallback
    - ai.cloud_mode
    - ai.signed_in

  The bootstrap reader is intentionally separate so the AI shell can fall back
  to a safe default even if the profile store is empty.

================================================================================
5. MENU MODEL
================================================================================

  The AI window uses a simple menu bar with four submenus:
    - Model
    - Cloud
    - Log
    - Help

  Model submenu:
    - Suggestion: default model
    - Agent: fallback model

  Cloud submenu:
    - Local only
    - Cloud subscription
    - Sign in to Ollama
    - Sign out
    - Open Ollama web site

  Log submenu:
    - Send prompt
    - Clear log
    - Copy answer

  Help submenu:
    - About this window

  Ai_RefreshUi() keeps the checkmarks and status text in sync with the stored
  state after every menu change.

================================================================================
6. LAYOUT AND DRAWING
================================================================================

  The layout is a fixed client-size dialog-style arrangement:
    - header/status summary at the top
    - multiline prompt editor taking roughly one third of the body
    - centered owner-draw action row directly under the prompt editor
    - multiline read-only answer pane taking the remaining space
    - status line pinned to the bottom

  Current geometry is DPI-scaled through S(). Button widths are measured with
  Ai_MeasureButtonWidth() so the label text and icon always fit. The answer
  pane uses a monospace font so fenced code blocks and indentation remain easy
  to read.

  The Ollama icon is loaded from ollama.png in the executable directory, not
  from the current working directory. That keeps the icon visible after install
  and when the app is launched through a shortcut.

  Owner-draw buttons use Ai_DrawButton():
    - Green for Send
    - Blue for Copy, with a clipboard-style glyph
    - Red for Clear
    - Red for Close

  Only the Send button uses the Ollama image; Copy uses the clipboard glyph,
  and Clear/Close are plain text buttons.

  The button spec is stored in AiDialogData so WM_DRAWITEM can paint the
  current button set without hardcoded text comparisons.

  Known layout issue:
    - The shell still needs tightening for cramped widths.
    - Some button and field placements can overlap when the window is reduced.
    - That should be fixed before more AI UI elements are added.

================================================================================
7. MESSAGE FLOW
================================================================================

  WM_CREATE
    - Restores settings.
    - Builds the menu.
    - Creates the header, prompt editor, answer pane, buttons, and status line.
    - Applies the common 12pt dialog font to chrome and a monospace pane font
      to the text areas.
    - Populates the initial status text and opens the answer pane with a
      startup line.

  WM_SIZE
    - Repositions all child controls.
    - Keeps the prompt editor around one third of the body height.
    - Centers the action row under the prompt editor.
    - Lets the answer pane use the remaining space.

  WM_COMMAND
    - Handles model/cloud/sign-in/log/help commands.
    - Send triggers Ai_DoSend().
    - Copy, Clear, and Close are also routed from their owner-draw buttons.
    - Copy answer uses the rendered answer range, not the whole log buffer.

  WM_CONTEXTMENU
    - Right-click on the answer pane opens a small popup menu with Copy.
    - That menu calls the same answer-copy path as the Log submenu and Copy
      button.

  WM_DRAWITEM
    - Paints the owner-draw buttons through Ai_DrawButton().

  WM_CTLCOLORSTATIC / WM_CTLCOLOREDIT
    - Uses normal window colors for the edit/static controls.

  WM_DESTROY
    - Deletes the font.
    - Releases the state block.
    - Clears the global window handle.

================================================================================
8. SEND BEHAVIOUR
================================================================================

  Ai_DoSend() now sends the current prompt to Ollama on localhost on a worker
  thread and returns immediately to the UI.

  Cloud login gate:
    - If cloudMode is true and signedIn is false, Ai_DoSend() opens the Ollama
      sign-up page and returns immediately.
    - That keeps the local transport path isolated from the sign-in redirect.
    - Real cloud request handling stays a separate follow-up slice.

  Current request path:
    - POST http://127.0.0.1:11434/api/generate
    - send the selected model and prompt as JSON
    - stream the response and post completion back to the window when the
      request is finished

  Before sending, the AI window prefixes a short markdown instruction so code
  answers are more likely to come back fenced and indentation-safe.

  The output pane shows the user's question first, then the Ollama reply or a
  short error message if the local service is not reachable.
  The current follow-up issue is that the rendered reply still does not match
  Ollama's own live output faithfully enough. Colours, links, and code afford-
  ances need to survive the render pass exactly the way the Ollama app shows
  them while the answer is streaming.

================================================================================
9. EXTERNAL DEPENDENCIES
================================================================================

  The AI shell depends on the existing project helpers:
    - dpi.h for S() scaling
    - ne_profiles.h for persisted settings
    - ne_ai_bootstrap.h for startup defaults
    - ne_ai_client.h for local Ollama responsiveness checks and the send/reply
      helper used by the AI window

  The actual Ollama probe remains separate from the window so the UI can stay
  responsive and the availability check can be reused from the main app.

================================================================================
10. MAINTENANCE NOTES
================================================================================

  - Keep the AI window implementation out of NSBEdit.cpp.
  - Keep the AI window locale-driven where possible; the maintenance dialog
    now uses locale keys, but the rest of the AI module still needs a full
    language pass.
  - Preserve the current local/default model split unless the product rules
    change again.
  - Keep cloud/subscription state separate from the local-only flow.
  - Keep the unsigned-cloud redirect separate from the local transport.
  - Keep the prompt/log UI simple until the layout bug is fully fixed.
  - Update this file whenever the AI shell gains real chat wiring or new menu
    actions.
