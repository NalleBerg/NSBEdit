================================================================================
  NSBEdit - MyStyle System Overview
================================================================================

  This note describes the shared system rules that travel with MyStyle from
  project to project.

  It is not a one-off NSBEdit quirk. It is part of the reusable style package
  that follows the author across Win32/C++ projects.

================================================================================
1. PUBLIC IDEA
================================================================================

  MyStyle treats the database and install flow as user-data infrastructure.

  The public rule is simple:
    - do not ship a personal database
    - do not overwrite an existing database on upgrade
    - do not hide where the runtime keeps its state

  The implementation may change from project to project, but the policy stays
  the same because the documentation style itself is portable.

================================================================================
2. WHAT USERS SHOULD EXPECT
================================================================================

  Installed mode:
    - state lives in %APPDATA%\NSBEdit\nsbedit.db and is preferred by both
      installed and portable launches whenever it exists
    - an installer may import a db from the install folder once
    - existing AppData state is preserved
    - if Ollama is present, install-time setup also pulls the two default AI
      models so the AI window can reply right away

  Portable mode:
    - state lives beside the exe in nsbedit.db only as a fallback when AppData
      is not yet available
    - if a portable db exists and AppData does not yet, the app migrates it up
      so both launch paths converge on one user database

  First-run fallback:
    - if no db exists anywhere, the app creates a fresh one

================================================================================
3. WHY THIS MATTERS
================================================================================

  The database contains FTP profiles and other saved settings.
  Protecting the database protects those user-specific values.

  That is why the same policy keeps showing up in MyStyle docs:
    - the data is portable
    - the rules are explicit
    - upgrades stay safe
