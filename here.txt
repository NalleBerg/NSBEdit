BIG PICTURE / GOAL
- The AI must UNDERSTAND a pasted image, both in CLOUD and LOCAL mode.
- Vision models (cloud deepseek-v4.1-flash, local llava:7b) already see
  images DIRECTLY.
- NON-vision / text-only models (cloud gpt-oss, deepseek-v4-pro, local
  qwen2.5-coder, ...) must understand images via DESCRIBE-THEN-ANSWER: a
  vision model describes the image to text, the text is injected into the
  prompt, and only text is sent to the answer model. (Ai-europe.txt.txt pt 4)
- MUST auto-detect vision vs non-vision models (via /api/show) so a text
  model NEVER gets a raw image (that caused hallucinations - the "tree" and
  "Click Me" wrong answers today).
- MUST NOT hardcode a describer model name (they get retired - see below).

THE BIG LESSON OF TODAY (why we rolled back)
- The multi-MINUTE "lag" at "Image understood" / on every query was NOT our
  code. The cloud model deepseek-v4.1-flash-CLOUD was RETIRED/flaky on
  ollama.com (it even replied "model not found. Try glm-5.3-flash:cloud").
  The fix was to pick a CURRENT cloud model (deepseek-v4.1-flash:1017-cloud
  works and is instant). Lesson: cloud model names/tags perish -> never
  hardcode one; detect/auto-pick instead.
