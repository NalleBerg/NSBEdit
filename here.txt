NSBEdit handover notes
Written: 2026-06-17

Current status
- The AI marker contract was changed away from markdown fences and now uses descriptive tags: `[[CODE_BLOCK_START]]` and `[[CODE_BLOCK_END]]`.
- The reply renderer currently shows the tags visibly, styles them separately from the code, and tries to stop the copied range at the end boundary instead of the whole log.
- The compile break from the signature change has been fixed. `AiCopyCode_EndBlock()` now takes an explicit end position and the stale call site in `ollama_ai.cpp` was updated.
- The remaining visible problem in the screenshots is visual correctness: the code coloring can still bleed and the end tag / copied span still needs a cleaner boundary strategy.
- The safest next technical step is to keep a raw AI reply capture, then render only after the actual raw markers have been detected and validated. That would avoid inferring boundaries from already-styled RichEdit content.

What to do next
- Continue with the raw-reply capture idea so the renderer can see the exact text the model produced before any formatting or truncation happens.
- Keep the contract strict: only `[[CODE_BLOCK_START]]` and `[[CODE_BLOCK_END]]` should define code boundaries in the explicit-marker path.
- If the model omits the end tag, synthesize the end marker only after the raw reply has been fully inspected, and keep the explanation text outside the copy span.
- If the version changes again before the next commit, keep all of this work under the same new version tag in the docs.
- Run `makeit.bat` without parameters before committing so the package reflects the current code and docs.
- Commit and push with a message that makes the marker-contract change obvious.

Notes
- The current debugging pain point is that the rendered output is not a faithful source of the raw model text.
- The start marker is better than it was, but the end boundary still needs a more deterministic handoff from raw text to styled output.
- Legacy markdown fences should stay out of the explicit-marker code path.
- The raw log should be temporary and only used until the boundary rules are stable.
- Keep local AI and cloud AI flows separate.
- Keep the model picker realtime, not restart-based.
- Portable mode should stay AI-free; installed mode can use Ollama locally.
